VHDL survival kit

Every answer has three parts

Whatever the question, your answer is always the same three blocks, in this order:

library ieee;                       -- 1) vocabulary
use ieee.std_logic_1164.all;        --    std_logic, std_logic_vector
use ieee.numeric_std.all;           --    ONLY if you do + - or compare numbers

entity my_circuit is                -- 2) the black box: pins
  port ( a, b : in  std_logic;
         y    : out std_logic );
end my_circuit;

architecture rtl of my_circuit is   -- 3) what it does
  -- internal signals are declared here (between "is" and "begin")
begin
  y <= a and b;                     -- statements go here
end rtl;
Exam habit. Even if the question says “write the architecture”, a correct library line and entity usually earn marks. Write them unless told not to.

Ports: name : mode type;

  • Modes: in (read only) and out (write only). An out port cannot be read inside (VHDL-93). If you need to read it, use an internal signal.
  • Types: one wire = std_logic; a bus of N wires = std_logic_vector(N-1 downto 0). Bit N-1 is the MSB, on the LEFT.
  • Semicolons separate ports. No semicolon before the closing ).
  • Several ports with the same mode and type can share a line: a, b, c : in std_logic;
entity MX_4S is
  port ( BUND_IN                : in  std_logic_vector(31 downto 0);
         SEL                    : in  std_logic_vector(1 downto 0);
         REGA, REGB, REGC, REGD : out std_logic_vector(7 downto 0) );
end MX_4S;
Quotes. One bit uses single quotes '1'. A vector uses double quotes "1010". "1" is a 1-bit vector, not a std_logic. Vectors that are compared or assigned must have the same length.

std_logic values you must recognise

ValueMeaningWhen you see it
'0' '1'driven low / highnormal logic
'U'uninitialisedstart of simulation, before anything drives the signal
'X'unknown / conflicttwo drivers fight
'Z'high impedancea three-state driver switched off
'-'don't careoutputs you let the synthesiser choose

Because these extra values exist, a with/select on a std_logic(_vector) is never complete without when others.

Internal signals = wires inside

A port is a pin on the box. A signal is a wire inside it, declared between is and begin.

architecture dataflow of circuit2 is
  signal x, y, z : std_logic;      -- internal wires
begin
  x  <= a xor b;
  y  <= a and b;
  z  <= x and y;
  f1 <= x xor y;
  f2 <= (z nand y) nand c;
end dataflow;

You will use signals for: helper selectors (abc <= a & b & c;), counters (signal count : unsigned(3 downto 0);) and shift registers.

Operators and the precedence trap

GroupOperatorsNote
Logicaland or nand nor xor xnor notwork bit-by-bit on whole vectors
Relational= /= < <= > >=result is boolean (for conditions)
Arithmetic+ - *only on unsigned / signed (numeric_std)
Concatenation&glues bits: "00" & a
The VHDL surprise. and and or have the SAME precedence. y <= a or b and c; is a compile error. Write (a or b) and c or a or (b and c). not is applied first. A chain of the same operator (a and b and c) is fine. nand/nor can never be chained.

Example with a = "1100", b = "1010": a and b = "1000", a or b = "1110", a xor b = "0110", not a = "0011".

<= has two meanings: as a statement it assigns; inside a condition it means “less than or equal”. To avoid confusion in conditions, prefer < 4 instead of <= 3.

Numbers need numeric_std

A std_logic_vector is just wires — "1100" could be 12 or −4. To do maths, say which: unsigned(...) or signed(...).

use ieee.numeric_std.all;

sum  <= std_logic_vector(unsigned(a) + unsigned(b));
big  <= '1' when unsigned(a) > 9 else '0';      -- compare with an integer
next <= std_logic_vector(unsigned(a) + 1);
clear <= (others => '0');                       -- all bits 0, any width
Never use std_logic_unsigned / std_logic_arith (non-standard). a + b directly on std_logic_vector does not compile with numeric_std — by design.

Chapter 3 also shows gate delays (after 5 ns, transport), generics and configurations. Delays are simulation-only and are not part of your coding questions.

Concurrent statements vs process

  • Statements directly after begin are concurrent: all exist at once, the order of lines does not matter. when/else and with/select live here.
  • if, case, for are sequential: only legal inside a process.
  • One driver rule: a signal is assigned by ONE concurrent statement only. Two concurrent statements on the same signal = short circuit → 'X'. (Inside one process, the last assignment wins — that is allowed.)
  • Registers and counters are always a process with a clock edge.

The error checklist (the doctor loves “find the errors”)

  1. port, not ports; entity name is; architecture arch_name of entity_name is.
  2. (7 downto 0), never (7..0).
  3. Signals assign with <=; := is for variables; => is only for port maps / case / others.
  4. Missing ; (after library, signal declarations, statements) or extra ; before the port list's ).
  5. Names: start with a letter, no spaces, no __, not a reserved word (in, signal, others …), end name matches.
  6. Types must match: std_logic vs BIT, vector widths (8 bits into 4 bits is an error).
  7. Reading an out port on the right side.
  8. with/select without when others; branches separated by ; instead of ,.
  9. when/else condition written as when sel (must be sel = '1'), or missing final else (latch).
  10. a or b and c without parentheses.

Lesson 1 · exam question 1 (5 marks) · about 45 minutes

when / else — conditional signal assignment

The shape

target <= value_1 when condition_1 else
          value_2 when condition_2 else
          ...
          value_n;                      -- final value: ALWAYS write it

Read it aloud: “target gets value_1 when condition_1, else value_2 when condition_2, …, else value_n.”

  • ONE target, written once, then <= once.
  • Each value has the same type as the target ('1' for std_logic, "0101" for a 4-bit vector).
  • Each condition is a boolean expression: a = '1', sel = "01", unsigned(x) < 4.
  • ONE semicolon at the very end.
  • It goes in the architecture after begin, NOT in a process.

Priority: the first true condition wins

The conditions are tested from top to bottom. As soon as one is true, the rest are ignored. The hardware is a chain of 2-to-1 muxes; the first condition sits nearest the output.

y <= "00" when a = '1' and b = '1' else
     "01" when a = '1'             else
     "10" when b = '1'             else
     "11";
abywhy
1100first line true
1001first false, second true
0110third line
0011final else
Rule. Put the most specific condition first. If you swap the first two lines, a = b = 1 gives "01" and the "00" line can never be reached — and it still compiles!

Never forget the final else

y <= a when sel = '0';              -- NO else → a LATCH (memory)
y <= a when sel = '0' else b;       -- correct: pure combinational

Without a final value, the circuit must “remember” y when sel = 1 → the synthesiser builds a latch. It compiles with only a warning, so it is a classic exam trap. The same happens with else unaffected or else y.

Exam phrase: “a when without else → consequence in one word: latch.”

Exam recipe (5 marks)

  1. Write library ieee; use ieee.std_logic_1164.all; (+ numeric_std if you compare numbers).
  2. Write the entity from the question (names exactly as given; bus = std_logic_vector).
  3. Find the cases where the output is NOT the default. Write one line per case — the most important (highest priority) case first.
  4. Finish with the default as the final else.
  5. Check: one target, one <=, quotes right, one ; at the end.

The next steps show the six patterns the doctor uses.

Pattern A — truth table / Σm

Sheet 1 Q6 (doctor's solution): F3 = 1 for LMN = 001, 110, 111.

F3 <= '1' when (L = '0' and M = '0' and N = '1') else   -- row 001
      '1' when (L = '1' and M = '1')             else   -- rows 110, 111
      '0';
  • Each 1-row becomes a condition: 0 → = '0', 1 → = '1', joined with and.
  • Two rows that differ in one bit can be merged (that bit is dropped) — optional.
  • Everything else → final '0'.

Alternative: build a helper vector and compare it: f <= '1' when lmn = "001" or lmn = "110" or lmn = "111" else '0';

Pattern B — multiplexer

MX_OUT <= D3 when (SEL = "11") else
          D2 when (SEL = "10") else
          D1 when (SEL = "01") else
          D0 when (SEL = "00") else
          '0';

A 2:1 mux is the smallest case: y <= a when sel = '0' else b;. N inputs need log₂N select bits (4 → 2, 8 → 3). For buses, the same line switches whole vectors.

Pattern C — priority encoder / “index” questions

When conditions overlap and order matters, when/else is perfect. ELE-413 Q3 (doctor counts positions from 1):

INDEX <= "100" when X(3) = '1' else
         "011" when X(2) = '1' else
         "010" when X(1) = '1' else
         "001" when X(0) = '1' else
         "000";

Lecture version (index from 0, plus a valid flag):

y <= "11" when w(3) = '1' else
     "10" when w(2) = '1' else
     "01" when w(1) = '1' else
     "00";
valid <= '0' when w = "0000" else '1';
Highest wins → test the top bit first. Lowest wins → test bit 0 first. An enable always goes on the first line.

Pattern D — decoder (with enable)

y <= "0000" when en = '0' else       -- enable first: overrides everything
     "0001" when w = "00" else
     "0010" when w = "01" else
     "0100" when w = "10" else
     "1000";

Output line number w is 1 (one-hot). For a 3:8 decoder use 8-bit patterns. Active-low enable: test en_n = '1' for “disabled”.

Pattern E — ranges and comparisons

Sheet 1 Q10 written with when/else (needs numeric_std):

SZ_OUT <= "100" when unsigned(D_IN) < 4  else   -- 0..3
          "010" when unsigned(D_IN) < 10 else   -- 4..9
          "001" when unsigned(D_IN) < 16 else   -- 10..15
          "000";                                -- unknown

Because the first true line wins, test ranges from the smallest upwards. Comparator flags:

gt <= '1' when unsigned(a) > unsigned(b) else '0';
eq <= '1' when unsigned(a) = unsigned(b) else '0';
lt <= '1' when unsigned(a) < unsigned(b) else '0';

Pattern F — demux, three-state, “only one case is different”

y(0) <= x when sel = "00" else '0';      -- demux: 4 statements,
y(1) <= x when sel = "01" else '0';      -- 4 DIFFERENT targets
y(2) <= x when sel = "10" else '0';
y(3) <= x when sel = "11" else '0';

z  <= a when en = '1' else 'Z';           -- three-state buffer
y8 <= '0' when a = "00000000" else '1';   -- 8-input OR (Sheet Q16)

if/elsif ⇄ when/else (question bank Q18, Q20)

Same chain, same order, same final branch. The process form needs every input in the sensitivity list.

-- process form
process(a, b, j, k)
begin
  if a = '1' and b = '0' then step <= "0100";
  elsif a = '1' then           step <= j;
  elsif b = '1' then           step <= k;
  else                         step <= "----";
  end if;
end process;

-- one conditional assignment (outside any process)
step <= "0100" when (a = '1' and b = '0') else
        j      when a = '1' else
        k      when b = '1' else
        "----";

Lesson 2 · exam question 2 (5 marks) · about 45 minutes

with / select — selected signal assignment

The shape

with selector select
  target <= value_1 when choice_1,
            value_2 when choice_2 | choice_3,
            ...
            value_n when others;
  • with + ONE selector signal + select.
  • Branches separated by commas; ONE ; at the very end.
  • | means “or” between choices of the same branch.
  • Lives in the architecture after begin (not inside a process in VHDL-93).

Think of it as a truth table written in VHDL: one row per choice.

The four rules the compiler enforces

  1. Complete — every possible selector value is covered → end with when others (std_logic also has 'X','Z','U' …).
  2. Exclusive — no value may appear twice ("0011" in two branches = error).
  3. Constant — choices are literals or constants, never signals.
  4. No priority — all choices are compared at once (one wide mux), so the order of branches does not matter.
when / elsewith / select
Decides onany boolean conditionsthe value of ONE selector
Overlapallowed, first true winsforbidden
Catch-allfinal elsewhen others
Separatorselsecommas
Hardwarechain of 2:1 muxesone wide mux / lookup table

Several inputs → one helper selector

The selector must be ONE signal of known width. If the function has inputs a, b, c, glue them first:

architecture sel of func is
  signal abc : std_logic_vector(2 downto 0);   -- declare before begin
begin
  abc <= a & b & c;                            -- a becomes the MSB
  with abc select
    f <= '1' when "010" | "011" | "101",
         '0' when others;
end sel;

VHDL-2008 accepts with a & b & c select directly; the helper signal works everywhere, so always use it.

Enable + address: ea <= en & a; — the enable becomes the MSB and all the disabled rows fall into when others.

Exam recipe (5 marks)

  1. Library + entity.
  2. If the selector is several signals: declare a helper vector and concatenate them (MSB first).
  3. Write with … select, then target <= once.
  4. One branch per output value; join the input values with |.
  5. Last branch: when others;
  6. Check commas, quotes and the single final ;.
Shortcut: list whichever is smaller — the 1-rows (others → '0') or the 0-rows (others → '1'). The doctor does this in ELE-413 Q2.

Pattern A — Σm / truth table

entity Q1 is
  port ( w : in  std_logic_vector(1 to 3);    -- w(1) is the LEFT bit
         f : out std_logic );
end Q1;

architecture Behavior of Q1 is
begin
  with w select
    f <= '0' when "001",
         '0' when "110",
         '1' when others;
end Behavior;

The PDF has a typo (0'); every std_logic literal needs two quotes: '0'.

Pattern B — multiplexer

with SEL select
  MX_OUT <= D3  when "11",
            D2  when "10",
            D1  when "01",
            D0  when "00",
            '0' when others;

For bus inputs the others value is (others => '0').

Pattern C — ranges (Sheet 1 Q10)

Ranges like 0 to 3 are NOT allowed on a std_logic_vector selector, so list every value:

with D_IN select
  SZ_OUT <= "100" when "0000" | "0001" | "0010" | "0011",
            "010" when "0100" | "0101" | "0110" | "0111" | "1000" | "1001",
            "001" when "1010" | "1011" | "1100" | "1101" | "1110" | "1111",
            "000" when others;

Integer or enumerated selectors may use ranges: with n select level <= "00" when 0 to 3, …

Pattern D — decoder

with a select
  y <= "0001" when "00",
       "0010" when "01",
       "0100" when "10",
       "1000" when "11",
       "0000" when others;

With an enable, use the helper ea <= en & a; and choices "100", "101", "110", "111" (see bank S6).

Pattern E — ALU (question bank Q73)

Each value can be a whole expression. Arithmetic: convert → compute → convert back.

with op select
  y <= a and b                                     when "00",
       a or b                                      when "01",
       std_logic_vector(unsigned(a) + unsigned(b)) when "10",
       std_logic_vector(unsigned(a) - unsigned(b)) when others;

The full 16-operation ALU (with cin, a logic unit, an arithmetic unit and an output mux) is bank question S7 — very likely exam material because the question bank asks it in three styles.

Pattern F — code converters and lookup tables

with bcd select
  seg <= "1111110" when "0000",   -- 0
         "0110000" when "0001",   -- 1
         "1101101" when "0010",   -- 2
         "1111001" when "0011",   -- 3
         "0110011" when "0100",   -- 4
         "1011011" when "0101",   -- 5
         "1011111" when "0110",   -- 6
         "1110000" when "0111",   -- 7
         "1111111" when "1000",   -- 8
         "1111011" when "1001",   -- 9
         "0000000" when others;   -- blank

Converting between the styles

with op select
  r <= a and b when "00",
       a or b  when "01",
       a xor b when "10",
       not a   when others;
r <= a and b when op = "00" else
     a or b  when op = "01" else
     a xor b when op = "10" else
     not a;
process(state)
begin
  case state is
    when idle | terminate => data <= "0000";
    when increase         => data <= "1111";
    when maintain         => data <= "1010";
    when decrease         => data <= "0101";
    when others           => data <= "----";
  end case;
end process;
Bug hunt (lecture X1): y <= a when "00"; (; instead of ,), missing when others, when en instead of en = '1', when/else without final else.

Lesson 3 · exam question 3 (5 marks) · about 60 minutes

Registers & counters

Latch vs flip-flop

process(en, d)
begin
  if en = '1' then
    q <= d;     -- transparent
  end if;       -- no else: holds
end process;
process(clk)
begin
  if rising_edge(clk) then
    q <= d;     -- sampled once
  end if;
end process;

A latch follows D the whole time enable is 1. A flip-flop copies D only at the clock edge. if clk = '1' then is a LEVEL → latch, not a flip-flop.

Detecting the edge

EdgeUseOld form (recognise it!)
Risingrising_edge(clk)clk'event and clk = '1'
Fallingfalling_edge(clk)clk'event and clk = '0'

clk'event means “clk just changed”; and clk = '0' means it changed to 0 → falling edge. The doctor's timing questions use this old form.

The golden template — asynchronous reset

process(clk, rst)                 -- clock AND async reset in the list
begin
  if rst = '1' then                -- 1) reset first: acts immediately
    q <= '0';
  elsif rising_edge(clk) then      -- 2) then the edge
    if en = '1' then               -- 3) enable inside the edge
      q <= d;                      --    (no else = hold: correct!)
    end if;
  end if;
end process;

Everything you write in Question 3 is this template. Only the line(s) inside the edge change: q <= d (register), count <= count + 1 (counter), q <= sin & q(3 downto 1) (shift register).

Synchronous reset — the other shape

process(clk)                      -- ONLY the clock
begin
  if rising_edge(clk) then
    if rst = '1' then              -- reset INSIDE the edge
      q <= '0';
    elsif en = '1' then
      q <= d;
    end if;
  end if;
end process;
SynchronousAsynchronous
Actsonly at the clock edgeimmediately
Sensitivity list(clk)(clk, rst)
Shapeif edge → if rstif rst → elsif edge

Active-low reset: name it rst_n / rstn and test = '0'. Same for an active-low enable en_n = '0'.

Trap: async reset but process(clk) → simulation waits for a clock while hardware resets at once (mismatch).

Priority = order of the if / elsif

Reset > load > enable is simply the order you test them. Example (question bank Q12):

if Reset_n = '0' then
  count_i <= (others => '0');
elsif rising_edge(Clock) then
  if Load = '1' then             -- load beats enable
    count_i <= unsigned(R);
  elsif E = '1' then
    if UpDown = '0' then count_i <= count_i + 1;
    else                 count_i <= count_i - 1;
    end if;
  end if;
end if;
In a clocked process a missing else = hold (what a register should do). In a combinational process a missing else = accidental latch.

Registers: PIPO and generic width

entity pipo is
  generic ( N : positive := 8 );                 -- before port
  port ( clk, rst : in  std_logic;
         d        : in  std_logic_vector(N-1 downto 0);
         q        : out std_logic_vector(N-1 downto 0) );
end entity;

architecture rtl of pipo is
begin
  process(clk, rst)
  begin
    if rst = '1' then
      q <= (others => '0');                      -- works for any N
    elsif rising_edge(clk) then
      q <= d;
    end if;
  end process;
end rtl;

Shift registers: SISO, SIPO, PISO

First letter = how data comes in, last = how it goes out (P parallel, S serial). Use an internal signal q because the outputs read it.

Counters

library ieee;
use ieee.std_logic_1164.all;
use ieee.numeric_std.all;

entity up_count is
  port ( clk, rstn, e : in  std_logic;
         q            : out std_logic_vector(3 downto 0) );
end up_count;

architecture rtl of up_count is
  signal count : unsigned(3 downto 0);   -- internal, numeric
begin
  process(clk, rstn)
  begin
    if rstn = '0' then
      count <= (others => '0');
    elsif rising_edge(clk) then
      if e = '1' then
        count <= count + 1;              -- down counter: count - 1
      end if;
    end if;
  end process;
  q <= std_logic_vector(count);          -- convert for the port
end rtl;

Why count? (1) + needs unsigned; (2) q is out and cannot be read. N bits wrap: 1111 + 1 = 0000, 0000 − 1 = 1111.

Counter extras: mod-N, load, up/down, flags

-- mod-10 (BCD): wrap by hand
if count = 9 then
  count <= (others => '0');
else
  count <= count + 1;
end if;

-- load a value (synchronous)
if load = '1' then
  count <= unsigned(din);
elsif en = '1' then ...

-- up / down control
if up = '1' then count <= count + 1; else count <= count - 1; end if;

-- a flag OUTSIDE the process (combinational)
tc <= '1' when count = 9 else '0';

count = 9 works because numeric_std lets you compare unsigned with an integer. to_unsigned(5, 3) makes a 3-bit unsigned 5.

signal q_i : std_logic;                -- internal: we read it
...
elsif rising_edge(clk) then
  q_i <= q_i xor t;                      -- T: 1 toggles, 0 holds
end if;
...
q <= q_i;

JK: 00 hold, 01 reset, 10 set, 11 toggle. Use jk <= j & k; and a case jk is inside the edge (see bank R11). Q(next) = JQ' + K'Q.

Lesson 4 · exam question 4 (5 marks) · about 60 minutes

Timing diagrams

The 4-question method

  1. Which edge? rising_edge / clk = '1' after 'event → rising. falling_edge / clk = '0' after 'event → falling. Level test (if clk = '1' with no 'event) → latch.
  2. Reset sync or async? Inside the edge test → synchronous (only at edges). Before the edge test → asynchronous (immediately).
  3. Priority? Whatever is tested first (normally reset, then load, then enable).
  4. At every active edge, read the inputs just before the edge line and decide: reset / load / D / hold.
Drawing rule: draw a vertical line at every active edge. A flip-flop output can change ONLY on those lines (or when an asynchronous reset becomes active). Between them it is a flat line.

Worked: the doctor's Exercise 1 (falling edge)

process(reset, clk)
begin
  if (clk'event and clk = '0') then     -- falling edge
    if reset = '1' then                  -- synchronous reset (inside)
      Q <= '0';
    elsif enable = '1' then              -- synchronous enable
      Q <= D;
    end if;
  end if;
end process;

Q starts at 1. Dashed lines = falling edges (t = 4, 8, 12, 16).

Answers: (i) Reset synchronous. (ii) Enable synchronous. (iii) Reset has priority. (iv) Enable should NOT be in the list; Reset CAN be removed (only clk is needed for a synchronous design — keeping it is harmless).

Latch timing: transparent while enabled

process(en, D)
begin
  if en = '1' then
    Q <= D;
  end if;
end process;

While en = 1, Q copies every change of D. When en = 0, Q freezes at the last value.

Worked: the doctor's QA / QB question (8 points)

process(clock, D)
begin
  if clock = '0' then  QA <= D;   else  QA <= QA;  end if;
  if clock = '1' then  QB <= QA;  else  QB <= QB;  end if;
end process;
  • QA = latch transparent while clock = 0 (follows D), holds while clock = 1.
  • QB = latch transparent while clock = 1 (follows QA), holds while clock = 0.
  • So the D pulse while clock is high (t = 3) never reaches QA, and QA's short pulse at t = 4–5 never reaches QB.
  • Together: a master–slave pair → QB acts like a rising-edge flip-flop.

QA is missing from the sensitivity list, but the waveform is unchanged: QA only changes while clock = 0, when QB is holding anyway.

Signals vs variables in a clocked process

process(clk)
begin
  if rising_edge(clk) then
    a <= d;
    b <= a;        -- uses the OLD a → b is one clock behind
  end if;
end process;

Signals update after the process suspends. With a variable (v := d; b <= v;) b gets the new d — no extra delay.

Combinational waveform → equation (doctor's Ex. 4A)

  1. Each interval is one truth-table row (here a b c = 111, 110, 101, 100, 011, 010, 001, 000).
  2. Read f in each interval: 0, 0, 1, 1, 0, 1, 1, 1.
  3. Group: all rows with b = 0 are 1 → b'. With b = 1 only a=0, c=0 → a'c'.
  4. f = b' + a'c' → f <= (not b) or (not a and not c);

For a gate diagram (Ex. 5): write each gate output, build the 8-row table, then simplify.

Exam drawing checklist

  • Mark every active edge with a vertical line first.
  • Write the initial Q at the left.
  • At each line, look at reset → load → enable → D in priority order.
  • Flat lines between edges (except latches and async resets).
  • Ignore every input change that happens between edges (unless asynchronous).
  • If a signal changes exactly at an edge in the drawing, write your assumption (“value before the edge”).

Q1 · when / else

y <= v1 when cond1 else
     v2 when cond2 else
     v3;                 -- final else!
  • first true wins → most specific / highest priority first
  • conditions: a = '1', s = "01", unsigned(x) < 4
  • no else → latch
  • enable on the first line

Q2 · with / select

s <= a & b & c;           -- helper
with s select
  y <= '1' when "010" | "101",
       '0' when others;      -- always
  • commas between branches, one ; at the end
  • each value once; no ranges on vectors
  • list the smaller set (1s or 0s)
  • enable: ea <= en & a;

Q3 · clocked template

process(clk, rst)          -- async
begin
  if rst = '1' then
    count <= (others => '0');
  elsif rising_edge(clk) then
    if en = '1' then
      count <= count + 1;
    end if;
  end if;
end process;
q <= std_logic_vector(count);
  • sync: process(clk), reset inside the edge
  • active-low: rst_n = '0'
  • shift right: q <= sin & q(3 downto 1);
  • shift left: q <= q(2 downto 0) & sin;
  • mod-N: if count = N-1 then count <= (others => '0');

Q4 · timing

  1. Find the active edge (clk = '0' after 'event = falling).
  2. Reset inside edge = sync; before = async (immediate).
  3. Priority = order of if/elsif.
  4. At each edge use inputs just before it.
  5. Flat between edges; latches follow D while enabled.
  6. Sensitivity list: sync → (clk); async → (clk, rst); enable never.

Classic errors

  • ports → port; (7..0) → (7 downto 0)
  • ; before ) in the port list
  • => / := used for a signal → <=
  • a or b and c → parentheses
  • reading an out port; BIT vs std_logic; width mismatch
  • name mismatch in end / architecture of
  • '1' bit vs "1010" vector

Week 1 facts (theory)

  • HDL jobs: verification (simulate) and implementation (synthesise).
  • We design at RTL — highest level where synthesis is reliable.
  • FPGA: reprogrammable, no fab cost, higher unit cost. ASIC: custom, cheapest only at huge volume, mistakes permanent.
  • Zynq = processor (PS) + FPGA fabric (PL) on one chip.
  • Flow: VHDL → simulation → synthesis → implementation → bitstream → FPGA.
